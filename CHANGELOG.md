# Changelog

All notable changes to Mesh are documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.0.0/),
and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

Mesh is currently in **beta**. Pre-1.0 versions (`0.x.y`) may include breaking
changes between releases — the SQLite schema, IPC contracts, the `ModelClient`
interface, and the Analysis output schema are all free to change until `1.0.0`.
The stable `1.0.0` release ships once every item in the
[Production Checklist](./docs/DEPLOYMENT.md#production-checklist) passes.

  - **Per-Model pricing table** (in-repo, a snapshot not a live feed) with opus / sonnet / haiku family rates across all four token classes (fresh input, cache-read, cache-write, output), matched by family so new point releases price without edits. Service-tier aware (batch is half price, priority a premium).
  - **Pure cost layer** computes Notional Cost from token counts grouped by (model, service tier). Unknown models are counted in tokens but **flagged unpriced** and excluded from the total — never priced by a guess. Cost is computed on read from the pricing table, never stored, so a price change needs no cache rebuild.
  - **Surfaced** in Settings → *Usage data* as "≈ $X.XX at API rates — not money spent"; the clarifier travels with every dollar figure. New `usage:get-cost-summary` IPC + `sumTokensByGroup` aggregation.

- **Slice 52 (v7): Usage ingest + `usage_events` rebuildable cache.** The data spine for v7's Usage views (ADR-0009). Every assistant turn's token counts are derived from the Session JSONL into a new SQLite cache — never authored, always reproducible by re-sweeping.
  - **Migration `0006_usage_events`** adds the `usage_events` cache (with by-project / by-time / by-session indexes) and a `usage_ingest_state` per-file cursor. The upgrade-cycle harness covers it from v1.
  - **Pure derivation.** `parseUsageLine` maps one JSONL line → a `UsageEvent` (uuid-keyed, attributed to a Project by its containing folder's Encoded Path; `cwd` is provenance only). `tailParse` consumes only newline-complete appended bytes, so a growing session re-ingests just its new turns; a truncated/replaced file resets.
  - **Freshness.** An async startup sweep (after first paint, yielding between Projects so launch never blocks) populates the cache; the existing session watcher tail-ingests an open Project's new turns live; a **Rebuild usage index** control in Settings → *Usage data* wipes and re-sweeps from scratch. Re-ingest is idempotent by `event_id`.
  - **IPC.** New `usage:get-status` / `usage:rebuild` + a `usage:status-changed` event (drives the future Home indexing shimmer), added to the preload bridge and the typed `window.api` test fake.
  - **Tests.** Node: the pure parser, the repository (idempotent insert, cursor round-trip, wipe), and the sweep/tail (append-only ingest, shrink reset, Encoded-Path attribution) over a temp projects dir. Renderer: the Settings Usage section (status readout, rebuild action, live status updates).
- **Slice 51 (v7): Networked Claude Quota — opt-in top-bar chip.** First slice of v7 (Usage) and Mesh's first-ever outbound network call, ring-fenced per ADR-0011. A persistent top-bar chip shows the account-global Claude subscription **Quota** — the 5-hour and weekly windows, each with percent-used and a reset countdown.
  - **Opt-in, off by default.** A new Settings toggle ("Show Claude subscription quota") persists `quota_enabled`. While off, nothing outbound happens and no credential is read; the chip is hidden.
  - **Main-process `quota/` module**, isolated from the (future) Usage ingest pipeline. A pure `parseOauthUsage` transform (unit-tested against the endpoint's payload shape) feeds a `QuotaService` with on-demand fetch, a ~5-minute in-process cache, and 429/error/no-credential back-off that serves the last good snapshot rather than re-hammering the aggressively rate-limited endpoint.
  - **Credential handling.** The OAuth token is read from Claude Code's own credential (macOS Keychain via the `security` CLI, with a `~/.claude/.credentials.json` fallback) — *not* an `sk-ant-` key, and *not* Electron `safeStorage` (which only round-trips Mesh's own secrets). It is used solely in the `Authorization` header to `api.anthropic.com`, never persisted, logged, or sent to the renderer. The fetch carries the required `User-Agent: claude-code/<version>` header.
  - **Reduced-color-vision constraint.** Each gauge encodes headroom with fill length + a numeric % + a label; the fill is a single neutral tone at every level (no red/amber/green thresholds), and the accessible name carries the number and reset — legible with color removed.
  - **Tests.** Node: the pure parser (full / missing-window / malformed) and the service's opt-in gating, cache TTL, and 429-serves-last-snapshot with injected fetch + clock. Renderer: the chip's render/hide states and the pure reset-countdown formatter. New IPC surface (`quota:get-snapshot` / `is-enabled` / `set-enabled`) added to the preload bridge and the typed `window.api` test fake.

### Added
- **Slice 49 (v6): Portal PtyView host — scrollback survives Project navigation.** Fifth slice of v6 and the release's one user-visible fix (ADR-0008: renderer PTY view lifetime follows main-process PTY lifetime). Resuming a Session, scrolling its terminal, switching Projects, and coming back now lands on the exact terminal you left — buffer, scrollback, and selection intact.
  - **`<PtyHost>`** mounts at App level and owns one `PtyView` per live tab in the registry — created when the tab appears, disposed only when the tab leaves (PTY exit or explicit close), never on navigation. Placement mechanics: each slot gets a *stable wrapper element* that React portals into exactly once; the host then moves the wrapper between the Workspace's mount pane and its hidden holding container with `appendChild`. The imperative move preserves the subtree — portaling directly into a changing container would remount the view and dispose xterm, the exact bug this slice fixes.
  - **`state/pty-host.ts`** — a small placement store (`mountNode` + `activeSlotId`) plus the pure `placementFor` helper. `WorkspaceScreen` registers its PTY pane via callback ref (null on the `key`ed remount between Projects) and publishes the active slot; the pane itself is now an empty `.workspace-pty-mount` target.
  - **The Slice 39 reconnect path is deleted, not patched.** `PtyView` loses `existingPtyId` (and its documented buffer-loss caveat) and the `hidden` prop; it spawns its PTY exactly once, on mount. New `focused` prop grabs keyboard focus when the view takes the pane, so typing lands immediately after a tab switch or Project round-trip. Refit on portal-in comes free — the existing `ResizeObserver` watches the view's own container, which travels with the wrapper.
  - **7 new host tests** (`pty-host.test.tsx`): holding-container membership without a mount, active-slot occupancy, the no-remount guarantee (identical DOM nodes after an active-slot swap — the scrollback-preservation property asserted at DOM level), mount unregistration, disposal on registry removal, focused-only-when-mounted, and ptyId wiring back into the registry. The Slice 46 jump tests adapt their visibility observable (mount-pane containment instead of the deleted `hidden` prop) with unchanged semantics. Test count: 319 → 326.
- **Slice 48 (v6): Store conversions — live-sessions + notifications to Zustand vanilla stores.** Fourth slice of v6; completes the ADR-0007 consolidation. Behavior identical by design — Slice 46's tests pass unchanged, and the Slice 39 state-machine assertions carried over verbatim.
  - **`state/live-sessions.ts`** — the hand-rolled registry (Map + listener set + cached snapshot) becomes `createLiveSessionsStore()` (zustand vanilla). No-op semantics preserved via early returns before `set` (duplicate add, same-value update, unknown slot never notify). Aggregation helpers unchanged — they take a snapshot-shaped argument the store state structurally satisfies.
  - **`state/notifications.ts`** — new `createNotificationsStore(deps)` with an injected api seam (production binds `window.api.notifications` lazily). The renderer-as-cache stance is unchanged: actions write through IPC and wait for main's echo events; `setGlobalMute` never sets local state.
  - **Both context providers dissolve into event bridges.** `LiveSessionsProvider` / `NotificationsProvider` keep their names and mount positions but carry no context — they own the global subscriptions (pty:data/pty:exit → registry; created/updated/cleared → refresh; mute-changed → globalMute) over module-singleton stores. `useNotifications()` returns the same shape as before; `useLiveSessionsSnapshot` (no consumers) is dropped.
  - **Selector-based subscriptions per ADR-0007.** `useLiveTabsForProject` shallow-compares its Project's slice; `useSessionIndicator` / `useProjectIndicator` subscribe to booleans, with the 2 s recency flag driven by store changes + a 500 ms tick through a bail-out `useState` — PTY chunks and ticks no longer re-render consumers whose indicator state is unchanged (previously every registry mutation re-rendered every indicator).
  - **4 new granularity tests** (`live-sessions-selectors.test.tsx`): activity chunks don't re-render an unchanged indicator, other Projects' tabs don't touch unrelated indicators or tab lists (render-count pinned), and the pty:exit bridge flips the indicator when the last tab dies. Renderer test setup now resets both singleton stores between tests, the way a window reload would. Test count: 315 → 319.
- **Slice 47 (v6): Zustand navigation store.** Third slice of v6 — first step of the ADR-0007 state consolidation. `App.tsx`'s component-local navigation state (screen, open Workspace Project, Home selection, previous-screen restore for Settings, one-shot pendingJump, and the `jumpToSession` orchestration) moves into a Zustand vanilla store.
  - **`state/navigation.ts`** — `createNavigationStore(deps)` factory with an injected `listProjects` seam (production binds `window.api.projects.list`; tests inject a fake), mirroring the main process's injectable-dependency convention. The pendingJump key is a store-internal monotonic counter (previously `Date.now()` — strictly-increasing is the actual contract; the counter can't collide on fast consecutive jumps).
  - **`hooks/useNavigation.ts`** — the singleton store instance + a selector-based `useNavigation(selector)` binding via zustand's `useStore`, so components re-render only when their slice changes.
  - **`App.tsx` slims to a composition root** — providers, screens, menu-accelerator wiring, and sidebar-collapse plumbing. No `useState`/`useRef` navigation state remains; behavior identical (Slice 46's tests pass unchanged).
  - **13 new store tests** (`navigation-store.test.ts`, framework-free — no DOM, no React): initial state, Workspace open/goHome semantics (goHome hides but doesn't discard the Workspace), Settings round-trips (previousScreen restore, repeat-open no-clobber, toggle from any screen, no-op close), and the jumpToSession orchestration (skip re-fetch when the target Workspace is already open, resolve unfamiliar targets through the Project list, no-op on unknown Projects, strictly-increasing keys, consume clears only the one-shot).

- **Slice 45 (v6): Renderer test infrastructure — vitest jsdom project + React Testing Library + `window.api` mock harness + tracer test.** First slice of v6 (renderer hardening, PRD-v6). The test suite splits into two vitest workspace projects: `main` (the existing node-environment suite, untouched) and `renderer` (jsdom + RTL + user-event + jest-dom over `tests/renderer/`).   - **`tests/renderer/test-utils.tsx`** ships the typed `window.api` mock harness — the renderer equivalent of the main process's injectable-dependency convention. ## [0.3.1] — 2026-06-29

### Fixed
- **Renderer CSP blocked `data:` URIs — file-tree icons + bundled fonts broken in packaged build (#38).** Discovered in v0.3.0 after Slice 31's smoke test missed it. Symptoms: Material Icon Theme glyphs (Slice 26) all rendered as generic broken-image placeholders; bundled Inter / JetBrains Mono fonts silently fell back to system fonts. Root cause: `src/renderer/index.html` set `Content-Security-Policy: default-src 'self'; script-src 'self'; style-src 'self' 'unsafe-inline'`. The `default-src 'self'` directive inherits down to `img-src` and `font-src`, which banned `data:` URIs. Vite's production build inlines small assets as `data:image/svg+xml,…` / `data:font/woff2;base64,…` — every one of those loads got refused by CSP under the packaged `file://` build. In `pnpm dev`, Vite serves assets as separate same-origin URLs (no inlining), so `'self'` covered them and the dev workflow looked fine. Fix: relax the CSP to `… img-src 'self' data:; font-src 'self' data:`. `script-src` stays strict; `style-src` keeps `'unsafe-inline'` for inline JSX `style` props. Standard practice for Electron apps that bundle assets.
