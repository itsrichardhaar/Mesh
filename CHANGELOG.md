# Changelog

All notable changes to Mesh are documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.0.0/),
and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

Mesh is currently in **beta**. Pre-1.0 versions (`0.x.y`) may include breaking
changes between releases — the SQLite schema, IPC contracts, the `ModelClient`
interface, and the Analysis output schema are all free to change until `1.0.0`.
The stable `1.0.0` release ships once every item in the
[Production Checklist](./docs/DEPLOYMENT.md#production-checklist-100) passes.

## [0.2.0] — 2026-06-29

### Added
- **Slice 28: Scrollbars + focus + motion capstone.** Final v2 polish slice — cross-cutting concerns applied once, everywhere. Thin (8px) custom scrollbars across the app: Webkit `::-webkit-scrollbar` pseudo-elements + Firefox `scrollbar-width: thin` / `scrollbar-color`. Thumb uses `--border-subtle` by default, lifts to `--text-muted` on hover. The `border: 2px solid transparent; background-clip: padding-box` trick gives the thumb visual breathing room without a separate inset. Monaco's custom scrollbar tuned to match (8px via the `scrollbar` editor option, `useShadows: false` for a calmer look). xterm uses the browser's native scrollbar so picks up the global rules automatically.
- Global `:focus-visible` rule introduced at the document root — 2px `--accent` outline with `--radius-sm` corners, 2px offset. Per-component focus rules (top bar buttons, card title links, etc.) still win on specificity, so the global is a safety net for any focusable element that doesn't define its own.
- QA pass completed across all 4 theme/UI Mode combinations (Light+Sans, Light+Mono, Dark+Sans, Dark+Mono) on every primary surface (Top Bar, Home cards, sidebar, Workspace tabs, file tree, transcript, Pty Tab xterm, File Editor, Settings).
- **v2 ships.** All 10 slices closed; production build green; 165 tests pass.

- **Slice 27: Terminal palette (Mesh Light / Mesh Dark ANSI).** Fixes the v1 light-mode terminal-contrast bug — `xtermTheme()` in `PtyView` no longer falls back to xterm's dark-tuned ANSI defaults (yellow `#e5e510` against `#faf8f4` was unreadable). Two explicit 16-slot palettes ship as TypeScript constants: `MESH_LIGHT_ANSI` (derived from Solarized Light, yellow/orange warmed toward Mesh's peach so accents harmonize with the rest of the app) and `MESH_DARK_ANSI` (explicit values close to xterm's defaults — provided for symmetry so palette evolution is tracked in source rather than depending on the bundled xterm version).
- `xtermTheme(effective)` now spreads the chosen palette into the theme object; `background` / `foreground` / `cursor` / `cursorAccent` / `selectionBackground` continue to read from CSS tokens (`--bg-canvas`, `--text-primary`, `--accent`, `--accent-fg`, `--bg-elevated`), so theme/UI mode changes still propagate without re-creating xterm instances. The existing `MutationObserver` on `[data-theme]` pushes fresh palettes into live ptys mid-stream — flip the top bar theme toggle while a Claude session is running and the colors update without re-spawn.

- **Slice 26: File tree icons (Material Icon Theme).** Workspace file tree is no longer type-blind — every row now shows a VS Code-style icon between the chevron and the filename. Folders get colored variants by name (Material Icon Theme's built-in mappings: `src/` blue, `tests/` red, `docs/` purple, `node_modules/` grey, `.git/` red, plus dozens of other conventional folder names) and toggle between closed and open variants based on expand state. Files get type-specific icons (TS, JSON `{}`, markdown, YAML, etc.) plus dedicated glyphs for special filenames like `package.json`, `tsconfig.json`, `.gitignore`, `CHANGELOG.md`, `README.md`, `vite.config.ts`, `electron-builder.yml`. Coverage is the full Material Icon Theme set (1250+ icons) — anything VS Code has, Mesh has.
- `material-icon-theme` npm package added as a dependency. The package's prebuilt manifest (`material-icons.json`) is imported at build time; SVGs from `node_modules/material-icon-theme/icons/*.svg` are eager-globbed by Vite into a runtime URL map. Tree-shaking trims the emitted SVGs to the set actually loaded during a typical Workspace browse — disk footprint stays reasonable (~25 SVGs in this run; grows naturally as the user opens more file types). Bundle JS grew by ~1.7MB raw to carry the ~440KB manifest and the URL string table; gzip compresses heavily.
- `src/renderer/src/material-icons/loader.ts` — small util exporting `getFileIconUrl(filename)` and `getFolderIconUrl(name, isOpen)`. Resolution order for files: exact filename match → multi-segment extension walk (so `vite.config.ts` matches `config.ts` before falling back to `ts`) → default file icon. Resolution for folders: exact folder name (with open/closed variant) → default folder icon.
- `FileTree` row renders a 16px `<img>` between the chevron and the filename. 8px gap (was 4px). Chevron stays a separate element from the folder icon — the chevron is interactive (expand/collapse hit target), the icon is not.
- Ignored / hidden file treatment: text stays muted via the existing row classes; the **icon stays at full opacity** so the user can still identify file types in muted regions. Mute = "ignored," icon = "what kind of file."

- **Slice 25: Analysis content styling.** Each section of the Analysis now renders as a deliberate visual block, not a generic markdown dump. Section headers are wrapped in a new `AnalysisSection` component that pairs a Lucide icon with a small-caps title — `FileText` for Summary of Recent Sessions, `ListChecks` for Next Steps, `Lightbulb` for Suggested Improvements. Headers use `--text-sm`, `--weight-semibold`, `--text-secondary`, `--tracking-wide`. A subtle 120px-wide `--border-subtle` rule sits beneath each header for visual anchoring without dominating the content. Accent color stays reserved for CTAs (Slice 24 Analyze bar, Open Workspace button, etc.) — section headers do NOT use it.
- Next Steps render as a numbered list with custom filled circular badges (20px, `--accent-soft` background, number in `--text-primary`) replacing the native `<ol>` markers. Tabular numerals keep multi-digit lists aligned. Suggested Improvements render with 6px filled `--accent` dots via a `::before` pseudo-element — the controlled accent moment in Analysis content.
- Spacing made generous throughout the Analysis card: `--space-8` between sections, `--space-4` between items in a list, `--space-3` between a section header and its content. Card padding bumped to `--space-6`, border-radius to `--radius-lg`. Cramped v1 paragraph spacing replaced by considered "this is meant to be read" rhythm.
- `AnalysisSection` is a small wrapper component taking `icon` (Lucide icon type) + `title` + `children`. Open to reuse if other parts of the UI want the same heading treatment.

- **Slice 24: Unified Analyze bar + project header path.** v1's three separate Analyze banners (blue analyzing, green success-attribution, red error) and the silent never-analyzed state are now a single state-aware `AnalyzeBar` above the Analysis content. The Analyze button moves *inside* the bar, anchored right; it hides during in-flight rather than disabling+greying, since the spinner already conveys "something is happening." Four states drive the bar's content and tone (`neutral` / `info` / `success` / `error`): "Not yet analyzed" + `+ Analyze`, "Analyzing…" + spinner + no button, "Analyzed from N sessions (last 14 days) · Xm ago · <Model>" + `+ Re-analyze`, "Last attempt failed: <message>" + `+ Try again`. Plus icon (Lucide `Plus`) prefixes the button in every visible state.
- Model attribution now lives in the success bar message. The redundant `AttributionFooter` (and its `.analysis-attribution` CSS) at the bottom of the Analysis content is removed.
- Project header restructured as a single inline row: title (`--text-2xl`, `--weight-semibold`, `--tracking-tight`), tilde-shortened source path (`--text-muted`, ellipsizes via `text-overflow: ellipsis`, `title` attribute on the span shows the full untildified path on hover), and auto-subtitle (`--text-secondary`). Path occupies the flexible middle slot so long paths take the hit, not the title or subtitle.
- `src/renderer/src/util/tildify.ts` — replaces `/Users/<name>` (macOS) or `/home/<name>` (Linux) with `~` for display. Heuristic, not exhaustive: paths outside those roots are returned unchanged. Mesh's v1 is macOS-only so this covers the case; Linux is future-proofing for v1.x installers.
- New `BarTone` type exported from `ProjectDetail` for downstream consumers that want to drive their own bars in the same vocabulary.

The Sessions list is no longer an always-visible middle column; it lives inside the Sessions tab as a 280px sub-column to the left of the transcript / Pty Tab area. Settings IPC only handles strings, so the boolean is serialized as `'true'` / `'false'`.

Without the bump, the Sessions tab fell back to a stacked-vertical layout instead of side-by-side columns.

- **Slice 22: Home cards reframe + sidebar Active/Idle/Source-Missing pills.** The Home Screen's right pane is now a "recent triage" cards grid — the top 12 Projects with activity in the last 14 days, ranked newest-first. Hidden and Source-Missing Projects are excluded from cards (sidebar still shows them); Projects active >14 days ago are also excluded. The auto-fill 280px CSS grid keeps cards roughly card-sized on any window width. Cards show: title (link to Analysis), auto-subtitle (muted), inline metrics row (`Xm ago · N sessions · N files`), analysis status (`Analyzed Xh ago` / `Never analyzed`), and an `Open Workspace →` CTA anchored to the bottom-right. Empty state when there are no recent Projects: `No recent projects` headline + paragraph pointing the user at the sidebar. The title is a `<button>` with a stretched `::after` pseudo-element that covers the whole card surface — clicking anywhere outside the CTA routes to the title's action (open Analysis). The `Open Workspace →` button is a sibling positioned with `position: relative; z-index: 1` so it intercepts clicks before the stretched surface does. Both interactive elements have distinct `aria-label`s (e.g., `Open Mesh analysis` / `Open Mesh Workspace`) so screen readers announce destinations clearly. Tab order: title link → CTA, two distinct focus stops per card.

Caching is per-card-mount; reordering the grid re-fetches on remount (acceptable for v2; batch IPC is a future optimization if needed).

With nothing selected, the right pane shows cards; with a Project selected, it shows `ProjectDetail`. Clicking the wordmark from inside an Analysis or from another screen returns to cards view.

The search field, project list, and footer all live inside the collapsible body.

- **Slice 19: Typography foundation + Mono/Sans toggle.** v2's first slice — lays the design plumbing the rest of v2 builds on. Inter (sans) and JetBrains Mono (mono) ship as self-hosted variable fonts via Fontsource (`@fontsource-variable/inter`, `@fontsource-variable/jetbrains-mono`); both register their `@font-face` rules on import. Typography tokens added: `--font-sans` / `--font-mono` / `--font-ui` (the last flips based on UI Mode), size scale (`--text-xs`/`-sm`/`-base`/`-md`/`-lg`/`-xl`/`-2xl`), weight scale (`--weight-regular`/`-medium`/`-semibold`), line-height scale (`--line-tight`/`-normal`/`-relaxed`), letter-spacing scale (`--tracking-tight`/`-normal`/`-wide`), and `--radius-base`. `:root` now reads from these tokens instead of inlined font/size values. A new `[data-ui-mode='mono']` block on `<html>` flips `--font-ui` to `--font-mono`, tightens `--radius-base` from 8 → 4px, and nudges `--tracking-normal` to `0.01em` for that CLI feel.
- `UiModeProvider` (`src/renderer/src/theme/UiModeProvider.tsx`) — mirrors `ThemeProvider`'s shape exactly. Hydrates from the `ui.mode` settings key on mount, sets `data-ui-mode` on `<html>`, persists on change. `useUiMode()` hook exposes `{ mode, ready, setMode }`. Wrapped into `App.tsx` inside `ThemeProvider`. Default = `sans` (matches v1 visual; no jolt on first v2 launch).
- First-paint UI Mode write in `main.tsx` (synchronous, before `createRoot().render()`) — CSP forbids inline scripts so the first frame would otherwise paint with whatever `data-ui-mode` defaults to in CSS before React mounts. Setting it to `'sans'` synchronously ensures the first paint is correct for the default case; UiModeProvider overrides this once the persisted preference hydrates.
- `UiModePreference` type + `isUiModePreference` guard in `shared/types.ts` (`'sans' | 'mono'`). `UI_MODE_PREFERENCES` array exported for iteration.
- Settings → Appearance gains a UI Mode fieldset below the Theme picker. Two radio options (`Sans` / `Mono`) using the same `.theme-option` visual pattern. Fieldset has a visible `UI Mode` legend (Theme picker's was visually-hidden; UI Mode needs the label since it's a new concept).
- Monaco (`FileViewer`) and xterm (`PtyView`) `fontFamily` strings now lead with `'JetBrains Mono Variable'`. Existing `'SF Mono', Menlo, …` fallback chain preserved so behavior degrades gracefully if the variable font fails to load.

Positioned `fixed` over the window's drag region with `-webkit-app-region: no-drag` so clicks reach the button while the surrounding strip remains draggable.

- **Slice 17: Multi-tab Pty Tabs + lifecycle.** The Workspace right pane (Sessions mode) now hosts an unbounded number of live `claude --resume` sessions side-by-side. Each `Resume in terminal →` click opens a new tab in a strip above the xterm area; previously-resumed tabs stay DOM-mounted with `display: none` so scrollback survives switching. Selecting a Session in the middle column deactivates the current tab and surfaces that Session's transcript (the tab stays alive in the strip; click it to return to the live terminal). A close (✕) button per tab sends SIGTERM with a 3 s SIGKILL fallback in `PtyManager.kill` so well-behaved children get a clean shutdown and runaway children don't strand. Tabs with output in the last 2 s show a ● activity indicator next to the label, ticking off automatically when the pty goes idle. `before-quit` consults `PtyManager.list()` — if any pty is alive, it shows a confirm dialog ("Mesh has N active Claude sessions. Quit anyway? Active work will be interrupted.") via `dialog.showMessageBoxSync`; Cancel aborts the quit, Quit anyway proceeds with `closeAll()`. The Home → Workspace round-trip preserves every tab and its scrollback because the Workspace itself stays mounted.
- xterm theme integration (carved out from Slice 18). The terminal palette is now derived from `getComputedStyle(document.documentElement)` against Mesh's design tokens (`--bg-canvas`, `--text-primary`, `--accent`, `--accent-fg`, `--bg-elevated`); a `MutationObserver` on `[data-theme]` pushes fresh palette into every live xterm instance the moment the attribute flips. Listening on the DOM attribute (rather than React's `effective` state) avoids the child-before-parent effect ordering trap — by the time React's `effective` propagates down, the attribute write may not have committed yet.
- `PtyManager.kill` now schedules a SIGKILL on a `SIGKILL_GRACE_MS = 3000` timer after sending SIGTERM. The timer is cleared automatically when the pty's `onExit` fires, so a clean-shutdown child never receives SIGKILL. `kill` is idempotent — a second call while the timer is in flight is a no-op. `closeAll` sends SIGTERM to everything immediately without scheduling the fallback (the renderer is going down anyway; the OS reaps stragglers).
- `MeshApi.pty.list()` IPC + preload bridge — exposes the manager's live-pty registry to the renderer for state inspection / future renderer-crash rehydration.
- `PtyManager` constructor takes optional `ScheduleTimeout` + `CancelTimeout` seams so the fake-timers test fixture can advance time deterministically.
- 3 new `PtyManager` tests: SIGKILL fires past the grace deadline, the grace timer is canceled when the pty exits during the window, and double-`kill` is idempotent.
- `PtyTabBar` component (`src/renderer/src/components/PtyTabBar.tsx`) — one tab per live pty with a ● dot driven by a 500 ms tick + per-tab `lastActivityAt` timestamp.
- `PtyView` gains `hidden`, `onPtyId`, and `onActivity` props so `WorkspaceScreen` can fan out multiple instances and drive the tab strip.
- `.pty-view[hidden] { display: none }` fix — without it, `.pty-view { display: flex }` would override the HTML `hidden` attribute, leaving all PtyViews stacked on top of one another.
- Drag region for the Home Screen — a real 28px flex child at the top of `.home-screen` (mirroring the Workspace header pattern). Resolves the issue where `.sidebar` and `.detail-pane`'s `-webkit-app-region: no-drag` left the user with no way to grab the Home window. Sidebar `padding-top` reduced from 40px to 12px and detail-pane from 60px to 32px to compensate.

- **Slice 16: Resume → single Pty Tab.** Wires up the previously-disabled "Resume in terminal →" button at the top of the Transcript pane. Clicking it spawns `claude --resume <sessionId>` in a real pseudo-terminal (cwd = the Project's Source Path) and pipes I/O into an `@xterm/xterm` viewport with the `FitAddon` keeping the terminal sized to its container. Input keystrokes route back through `pty.write`; a `ResizeObserver` on the container pushes `cols/rows` updates to the pty so the child process sees a consistent `COLUMNS`/`LINES`. Selecting another Session kills the current pty (Slice 17 will introduce tabs); `before-quit` SIGTERMs every live pty. When the `claude` CLI isn't on PATH the renderer surfaces a "Claude CLI not found" banner with a link to claude.com — no spawn happens.
- `node-pty` + `@xterm/xterm` + `@xterm/addon-fit` deps. `rebuild:electron`, `rebuild:node`, and `postinstall` scripts updated to compile `node-pty` alongside `better-sqlite3` against Electron's ABI.
- `PtyManager` (`src/main/pty/manager.ts`) — keyed registry of live ptys with a `PtySpawn` seam so the tests can inject a fake without pulling the native module. `create / write / resize / kill / list / closeAll`; ptys auto-deregister on exit so write-after-exit is a no-op. 8 fixture tests cover spawn args, ptyId routing for data events, write/resize/kill happy paths, unknown-id failure modes, non-positive resize rejection, auto-removal on exit, fleet teardown via `closeAll`, and unique-id generation when callers don't supply one.
- `resolveClaudeBinary()` — invokes the user's login shell to find `claude` on the full PATH (Electron GUI apps inherit launchd's PATH, which doesn't include shell-rc additions, so a naive `command -v` would miss `~/.local/bin` etc.). Returns null on miss; rejects alias / function output by requiring an absolute path.
- `MeshApi.pty.{create, write, resize, kill, onData, onExit}` IPC. `pty.create` returns a typed `PtyCreateResponse` envelope (`{ ok: true, ptyId }` or `{ ok: false, code, message }`) so failure metadata survives the IPC boundary — Electron strips custom properties off rejected errors.
- Renderer: `PtyView` component owns the xterm lifecycle. Builds the terminal on mount, queues user keystrokes until the spawn round-trip completes, listens for streamed data + exit events, kills the pty on unmount. `ResizeObserver` propagates layout changes to both `FitAddon.fit()` and `pty.resize()` so the child stays in sync with the viewport.
- `shared/pty.ts` defines the wire shapes; the xterm stylesheet is imported once globally from `main.tsx`.

### Deferred (revisit when Slice 17 lands)

Slice 17 will derive the full theme object from CSS variable values + listen on `[data-theme]` attribute changes so live ptys update in lock-step with the app palette (this is the carve-out left over from Slice 18).

- `friendly(err)` in the renderer strips Electron's `Error invoking remote method '…': Error:` wrapping from pre-flight errors before they hit the banner.
- 3 new model-client tests: schema retry succeeds on second attempt, double-failure raises `SchemaViolationError` after exactly 2 calls, and network errors never trigger the retry.
