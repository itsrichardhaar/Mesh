# Renderer PTY view lifetime follows main-process PTY lifetime

Mesh v6 moves `PtyView` rendering out of `WorkspaceScreen` into a persistent App-level **`<PtyHost>`** that owns one view per live Pty Tab and portals the active tab's view into the visible Workspace's PTY pane via `createPortal`. Views whose Workspace is not visible (or whose tab is not active) render into an App-level offscreen holding container (`display: none`), so the xterm DOM — and therefore scrollback — persists across Project navigation.

This completes an alignment Slice 39 (v5) started. Slice 39 decoupled PTY *state* lifetime from `WorkspaceScreen` (the live-sessions registry lives at App level; main-process PTYs survive navigation) but left *view* lifetime coupled: `WorkspaceScreen` is `key`ed by `encodedPath`, so switching Projects unmounts every `PtyView`, whose cleanup calls `term.dispose()`. The Slice 39 workaround — an `existingPtyId` reconnect path that adopts the still-alive PTY into a fresh xterm instance — preserved the process but not the buffer, a caveat documented in the component itself. With the portal host, a PtyView is created once when a PTY spawns and disposed only when the PTY exits or its tab is explicitly closed; **the reconnect path is deleted, not patched**.

## Considered Options

- **Serialize-and-restore** via `@xterm/addon-serialize` (snapshot the buffer on unmount into the live-sessions registry, replay on remount) — rejected: ~40 lines, but it patches the symptom. Restore fidelity is imperfect (cursor state, in-flight TUI repaints), the reconnect seam and all its edge cases survive, and it adds a second buffer-lifetime concept instead of removing one. Wrong direction for a hardening release.
- **Un-keying `WorkspaceScreen`** (keep one instance mounted, swap the `project` prop) — rejected: the `key` is load-bearing by design — file tree, selected session, and mode tabs all intentionally reset on Project switch. Removing it means auditing and manually resetting every piece of Workspace state to fix a problem that belongs to one component family. High blast radius for the wrong reason.
- **Status quo** (accept scrollback loss) — rejected: it is a felt daily paper cut, was explicitly acknowledged as deferred in Slice 39, and the 2026-06 assessment flagged it as one of the accumulating weaknesses v6 exists to close.
- **Fixed App-level layer positioned over the Workspace's PTY pane** (no portals; absolutely-positioned views toggled by visibility) — not chosen, but recorded as the **escape hatch within the same architecture**: if `createPortal` proves fragile for xterm specifically (focus or measurement issues when the DOM node moves between containers), the same lifetime guarantee holds with positioning mechanics instead of portal mechanics. The decision this ADR records — view lifetime = PTY lifetime, owned above the Workspace — survives either mechanism.

## Consequences

- **`<PtyHost>` mounts at App level** and derives its children from the live-sessions registry (one `PtyView` per live tab, keyed by slot). It never unmounts on navigation.
- **The active Workspace registers a mount node** for its PTY pane; `PtyHost` portals the active tab's view into it. No mount node (Workspace closed, other screen active) → the view sits in the hidden holding container.
- **`existingPtyId` and its reconnect branch are removed** from `PtyView`, along with the mount-time spawn-vs-attach decision. `PtyView` regains a single lifecycle: spawn on create, dispose on PTY exit or explicit tab close.
- **Focus and resize on portal-in:** the view refits (existing `FitAddon` + `ResizeObserver` machinery — the observer watches the view's own container, which travels with the portal) and takes focus; portal-out returns focus to the document flow. Focus behavior is an explicit HITL item in the v6 closing slice.
- **Scrollback survives** Project navigation, screen switches, and sidebar/layout changes, bounded only by xterm's existing `scrollback: 10_000` setting.
- **The host's state machine ships with renderer tests** (which view portals where; holding-container membership; disposal on exit/tab-close) under the v6 test policy. Terminal *rendering* remains HITL-verified — xterm does not run meaningfully in jsdom.
- **Memory profile is unchanged in kind**: hidden-but-mounted PtyViews were already the within-Workspace behavior (the `hidden` prop, Slice 17); the host extends the same policy across Projects. All views still die with their PTYs, and all PTYs still die with Mesh (ADR-0002-era process model unchanged).
